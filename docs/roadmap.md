# 남은 작업

현재 제품 기능은 미구현이다. 프로젝트 구조와 게이트 자기검증을 갖췄으며 모든 제품 시나리오는 미구현 표식으로 남아 full 검증을 실패시킨다. 체크는 해당 시나리오 E2E가 실행되어 통과한 뒤에만 갱신한다.

| 상태 | 작업 | 관련 시나리오 |
| --- | --- | --- |
| 미구현 | Task·입력·설정 파서와 정규화, 버전·스냅샷 | SC-01~07, SC-31~34, SC-40 |
| 미구현 | SQLite 원자적 저장·순서·자원 선점 | SC-01~10, SC-42 |
| 미구현 | 시작·종료검사, 명령 프로토콜, 호출·반복 예산 | SC-11~15, SC-34~35, SC-38 |
| 미구현 | 간격·cron·기간 보충·커서 복구 | SC-16~19, SC-36~37 |
| 미구현 | 프로세스 그룹·중단 복구·수동 확인·취소 | SC-20~24, SC-38~39, SC-42 |
| 미구현 | 설정 변경·저장 실패·출력 상한·로그 정리 | SC-25~27, SC-33, SC-40 |
| 미구현 | CLI 상태·로그·오류·데몬 경계 | SC-41 |
| 미구현 | 실제 이슈 수정·자료 변환·기간 리포트 | SC-28~30 |

구현 순서는 의존성을 따른다. 각 단계에서 가짜 실행기의 전체 흐름을 먼저 통과시키고 실제 환경 연결로 넘어간다. 게이트와 테스트의 중요 판정은 무력화 변형을 독립 리뷰어가 재현한다. 실제 출시 전에는 Linux amd64와 arm64에서 실행하고 L3 결과와 건너뜀 사유를 기록한다.

## 후속 개발에서 결정하거나 추가할 것

- JSON·YAML·cron 파서 구현 시 퍼징을 추가한다. 현재 파서가 없어 빈 퍼징 테스트를 두지 않는다.
- 실제 제품 의존성을 도입하면 govulncheck와 그 실행 위치를 정한다. 현재 verify.sh는 취약점 검사를 수행하지 않는다.
- 릴리스 버전 스탬핑과 --version은 기존 v1 CLI 계약에 없으므로 사용자와 계약을 확정한 후 추가한다.
- 커버리지 목표와 마이크로벤치마크는 현재 도입하지 않는다. 시나리오의 실효성을 우선하며 성능 병목이 관측되면 측정 범위를 정한다.

기능 제외 목록은 [요구사항](requirements.md) 1절에 유지한다. 이 목록은 새 제품 기능을 암묵적으로 추가하는 계획이 아니다.
