# 아키텍처와 경계

현재 디렉터리는 구현을 위한 골격이다. SQLite 저장소·프로세스 실행기·스케줄러·CLI 기능은 아직 없다. 아래 책임 분리는 [사용자 시나리오](scenarios.md)를 구현할 때 따를 구조이며, 형식·기본값·원자적 저장 단위는 [요구사항](requirements.md)에 정의한다.

## 의존 방향

| 경로 | 책임 | 허용하는 프로젝트 의존 |
| --- | --- | --- |
| internal/domain | Task·접수·Run·Step 상태, 순수 전이와 예산·키 규칙 | 없음 |
| internal/ports | 유스케이스가 요구하는 저장·명령·시계 등 협력자 계약 | domain |
| internal/usecases | 접수·일정 발행·실행·복구·취소 흐름 조합 | domain, ports |
| internal/adapters | SQLite, OS 프로세스, 시계, 설정, CLI의 실제 입출력 | domain, ports |
| cmd/todoable | 실행 진입점과 실제 협력자 조립 | 위 제품 계층 |
| test | 호출자 관점 E2E와 테스트 지원 코드 | 위 제품 계층 |
| tools/archgate, tools/testreport | 구조 게이트와 테스트 실행 결과 판정 | 제품 계층 밖; 제품 코드가 의존하지 않음 |

정확한 허용 목록은 루트 archgate.json이 기계적으로 관리한다. 새 패키지는 계층 하나에 속해야 하며 제외는 근거를 명시한다. 도구는 자체 검증을 먼저 실행한 뒤 제품 판정에 사용한다.

CLI 입출력 변환은 adapters가 맡고 유스케이스 호출과 의존 조립은 cmd/todoable이 맡는다. adapters에서 usecases로 의존하지 않는다.

CLI와 데몬은 같은 로컬 DB에 짧은 트랜잭션을 기록한다. CLI는 작업 명령을 직접 실행하지 않는다. 데몬은 영속 요청을 읽고 명령 실행 의도를 커밋한 뒤 프로세스를 시작한다. 결과와 다음 단계는 함께 저장하며 결과 없는 변경 단계는 자동 재실행하지 않는다. 이 경계가 중복 외부 효과를 막는 복구 기준이다.

## 비결정적 입력과 인자

현재 시각, 난수·UUID, 환경변수·파일시스템·프로세스 상태는 adapters에서 관측하고 ports를 통해 전달한다. domain은 순수 판정만 수행한다. 실제 계층 금지는 archgate 설정으로 검사하며 설정이 열거하지 않은 우회까지 모두 검증한다고 주장하지 않는다.

usecases에 인자 모양 규칙 A·B를 적용한다. 인자 5개 이상 또는 같은 타입 인자 2개 이상을 금지한다. 협력자를 가진 인자 구조체는 한 함수에만 사용하며 해당 패키지에서 정의한 인자 필드는 모두 읽는다. 구조체 통째 전달·복사·반환을 피하고 필요한 협력자와 값을 명시한다. 죽은 읽기와 의미 없는 단정은 타입 검사로 보장할 수 없어 독립 리뷰가 확인한다.

## 구현과 검증 순서

먼저 순수한 입력·일정·상태 규칙과 실제 저장소를 만든 뒤 로컬 가짜 실행기로 CLI/데몬 전체 흐름을 검증한다. 가짜는 실제 어댑터와 같은 검증 규칙을 지키고 같은 조작에 대한 오류·반환값 대조를 거친다. 실제 에이전트와 외부 게시 연결은 그 뒤의 L3 검증이다.

프로세스 그룹 정지, PID 시작 식별값, 호출 슬롯, 충돌 자원, 시간 예산은 영속 상태와 함께 다룬다. 정상 비영 종료와 결과 불명을 구분하고 종료검사를 성공의 근거로 삼는다. 상세 복구·취소 계약은 요구사항 7~10절, 저장 원자성과 백업은 14절을 따른다.

현재 게이트는 Linux amd64·arm64를 대상으로 설정한다. full 검증의 race는 호스트에서 실행되므로 두 아키텍처의 실제 출시 실행 검증을 대신하지 않는다.
